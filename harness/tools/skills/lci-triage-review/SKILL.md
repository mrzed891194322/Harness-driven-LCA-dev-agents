# LCI 映射分流 · 04 reviewer

内容按已注入的官方 PCFBench triage 英文口径。只读手检，无 triage MCP；你的任务是先尝试推翻当前判断，再决定是否批准，而非重做 executor 的顺序或复述其理由。

1. **锁定待反证结论**：读 `<plan>`、`workspace/runs/lci-triage-04/executor/checklist.json` 与 `artifacts/triage/triage.json`，缺文件则 reject。在裁决前先写出针对当前 `should_map` 的最强异议，再用题面和 picklist 检验它。只在计划内检索，不遍历仓库、不查询 openLCA；ROOT 不作 MARKET 组成，confidence 不影响裁决。
2. **若当前为 true，攻击制成边界**：从最强候选到 MARKET 的交付形态，尝试指出一个具体、尚未覆盖的材料或制造/加工缺口，说明题面/活动名依据；不能只问“是否均质”。若缺口成立且必须进一步分解，reject，要求重判受影响的轴与结论，不能在 comment 承认缺口却批准。若找不到成立的缺口，明确记录检验过的最强异议、为何不成立，以及候选为何已代表交付形态、无需额外制成步骤，之后才可 approve；“homogeneous commodity”“无独立零件”不是排除反证的依据。不要为反对而虚构工序，也不重拆候选已代表的生产链。
3. **若当前为 false，攻击分解必要性**：独立搜索整个采购项/通用品类，逐字点名最强 picklist 候选，不能只沿用 executor 的组分候选；再指出它仍缺少的具体 LCI 边界，以及分解将补上的子材料或制成活动。不要求所有拟拆子件本轮找到最终活动或当场全部映射；不得以子件未映射为由要求 B=no 或转 true。尚不能证明完整拆分、子件仍需展开或没有现成子件活动，均不能直接证明父项可被单一活动代表或所选整体候选已合理覆盖。若确实找不到整体候选，明确列出搜索过的用途/类别与最接近的逐字候选及其不适用依据，不编造命中。executor 或本轮审查遗漏整体候选搜索，必须 reject 补查；不能以“无同名”、已知物质不可用通用代理、配方精度或实物性能差异替代 LCI 缺口。找不到分解会修复的具体缺口时 reject 重评，不凭空发明合成路线来维护 false。
4. **检验反证质量与结构**：把事实、活动名信息和推断分开；清单中同时出现原料与成品不能证明库存包含关系，性能/用途差异须联系材料或生产边界才支持异议。逐字段核对 `axis_a.candidates` 为至多 3 个逐字在 picklist 的名称字符串，A=yes 须有候选；非空 `candidate_name` 也须逐字在清单。`reasonable_direct_match`、`must_decompose_first` 为字符串 "yes"/"no"，两轴 reason 非空；`decision_preview` 与 `should_map` 为一致的裸布尔，且仅 A=yes、B=no 为 true。rationale 须覆盖两轴且自洽。缺失、错位、类型错误或无依据的确定库存断言均 reject。
5. **裁决并交卷**：一次列全 issues，`where` 指字段/轴，`problem` 只指出证据问题与未被消除的异议，`expected` 写具体修复方向，不代写结论或要求风格修订；反馈不得预填 A/B（`reasonable_direct_match` / `must_decompose_first`）或最终布尔（`should_map` / `decision_preview`）的取值。提交 comment 按“最强异议 → 独立核查证据 → 异议成立/排除依据”记录；approve 必须包含对应分支的制成边界或整体候选检验。调用 `mcp__submit__submit`；reject 只传 verdict、issues、可选 comment，不传 summary、null 或 artifact；无法返工则 terminate。复审检验原 issues 的实质回应与受影响的轴，已解决问题无新证据不重开。
