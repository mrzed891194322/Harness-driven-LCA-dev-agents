# BOM 数量抽取 · 02 工作流

按序执行，不扩写。

1. **读技能与题面**：读本技能与题面（plan/query）。
2. **定目标/条数**：**读文前**只依题面定短清单与 N；**读文后严禁反扩清单**。每项「对象×所问指标」；题面用单数量词 +「and」连接的同材料/同路径连续工序（含 respectively）→ 计为 1 个合并对象（N=1），除非题面明确要求分开比；N=len(checklist)。
3. **读原文并抽取**：按清单在 `harness/knowledge/inputs/` 用 `grep` 定位、`read` 确认，写 `workspace/artifacts/bom/claims.json`。薄边界：**原文区间两端可保留**；同一清单项在原文有多个口径或对照值时可并列交。单位：题面点名要某单位、原文给另一基数（如每 100 份）时，按原文基数换算到题面单位，`evidence` 以 `[推断]` 开头，`text` 强制写算式与原文基数；其他情况照抄完整单位短语（含限定语），不缩短；不引入外部换算系数。合并：所问项仅给同单位分项时，只交分项相加总和（`[推断]`+算式），不另交分项；对 step2 合并对象，确认同单位同口径、不重叠分项后，只交相加总和（evidence `[推断]`，text 写算式），不另交分项；禁止跨指标乘除。**不交**未问分项、同值换单位重复条、定义常数、`value=null`。每条有 `claim_id`；`value` 照原文数值与正负号（换算/合并用结果值）；`unit` 按上；`text` 写口径与文件名+位置（换算/合并时含算式与原文基数）；`evidence` 只放含该数与单位的原文逐字引文，推断/换算/合并时以 `[推断]` 开头并写依据。
4. **核对**：调用 `check_claims(checklist=[清单项...])`，同时查数量（条数 vs N）与正确性（value/unit 在 evidence、evidence 在原文）。工具只提醒，不删改、不拦交卷。
5. **交付**：有告警时：逐条写清该 claim 与题面清单哪一项对应，以及改 / 挪笔记 / 保留 / 未解决及理由；**数量告警须单独处理**（不能用 OCR/证据解释一带而过）；**勿为凑 N 机械删条**；改完再核。多轮仍未解决可在 `submit` 说明相关 claim_id、剩余问题及原因后带错提交。原文完全无可答数字才 `abstained: true` + `claims: []`。

有 `<rework>` 时只改所列问题后再交付。
