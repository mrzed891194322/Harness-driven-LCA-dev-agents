# BOM 数量抽取 · 02 工作流

按序执行，不扩写。

1. **定清单/N（读文前）**：只依题面列短清单「对象×所问指标」；N=len(checklist)。题面把同材料/同路径连续工序用单数量词和 and（含 respectively）问成一项时，清单只列 1 项。读文后严禁反扩清单。
2. **读原文并抽取**：按清单在 `harness/knowledge/inputs/` 用 `grep` 定位、`read` 确认，写 `workspace/artifacts/bom/claims.json`。
3. **薄规则**（N 是清单项数，不是 claim 条数上限；**02 默认**，04 见下专段）：
   - **并列**：同一清单项在原文有区间两端或多个口径/对照值时，可并列交多条。
   - **单位**（02）：数值与单位只抄原文完整短语；禁止换算（含 MJ↔kWh 等）；不引外部换算系数。
   - **合并**：同一清单项仅给同单位、同口径、不重叠分项时，只交相加总和（`[推断]`+算式），不另交分项；禁止跨指标乘除。合并适用时只交相加总和，被加总的分项不算并列、勿另交；真多口径或区间两端仍可并列。
   - **不交**：未问分项、同值换单位重复、定义常数、`value=null`、清单外。
   - **字段**：每条有 `claim_id`；`value`/`unit`/`text`/`evidence` 按上；推断/合并的 evidence 以 `[推断]` 开头并写依据。
4. **核对**：
   - **02（executor 挂 `bom_claims_check` MCP）**：`check_claims(checklist=[清单项...])` → 有告警则改 → 再 check。多报/范围外类告警须删多余条后再 check；条数≠N 不硬卡。
   - **04（executor 无 check MCP、有 reviewer）**：写完 `claims.json` 后**结束本回合**；勿调用 `check_claims`（核对由 reviewer 强制 MCP）。
5. **交付**：多轮未解决须说明剩余错误及改不了原因再带错交。原文完全无数字才 `abstained: true` + `claims: []`。有 `<rework>` 时只改所列问题。

---

## 仅当你是 04 三件套 executor（无 check MCP、有 reviewer）时适用

- **题面契约（读文前）**：只依题面把清单写入本节点 runs 目录（注入里的「中间文件写到 …」路径）下的 `checklist.json`：`{"items":["对象×所问指标", ...]}`。读文后再写 claims；清单不进 claims schema。
- **同尺四口径**（与 `bom-claims-review` 同词）：
  1. **对象×指标×分母/边界匹配**：不因同文纳入，也不无据排除对照/同行对象。
  2. **单位**：仅当题面指定目标单位且原文无该单位值时，按精确物理常数同量纲换算，`value` 写换算后值，`evidence` 以 `[推断]` 开头写原文引文+算式；禁只换单位标签、禁外部经验系数。
  3. **区间**：区间=一项证据，不拆两端凑条数；题面问单值且原文有作者代表值→交代表值；否则按题面形态交一条。
  4. **abstain**：仅在所问量全文无直接依据；部分缺口在 `text` 注明，不清空。
