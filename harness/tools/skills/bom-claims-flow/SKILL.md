# BOM 数量抽取 · 02 工作流

按序执行，不扩写。

1. **定清单/N（读文前）**：只依题面列短清单「对象×所问指标」；N=len(checklist)。题面把同材料/同路径连续工序用单数量词和 and（含 respectively）问成一项时，清单只列 1 项。读文后严禁反扩清单。
2. **读原文并抽取**：按清单在 `harness/knowledge/inputs/` 用 `grep` 定位、`read` 确认，写 `workspace/artifacts/bom/claims.json`。
3. **薄规则**（N 是清单项数，不是 claim 条数上限）：
   - **并列**：同一清单项在原文有区间两端或多个口径/对照值时，可并列交多条。
   - **单位**：数值与单位只抄原文完整短语；禁止换算（含 MJ↔kWh 等）；不引外部换算系数。
   - **合并**：同一清单项仅给同单位、同口径、不重叠分项时，只交相加总和（`[推断]`+算式），不另交分项；禁止跨指标乘除。合并适用时只交相加总和，被加总的分项不算并列、勿另交；真多口径或区间两端仍可并列。
   - **不交**：未问分项、同值换单位重复、定义常数、`value=null`、清单外。
   - **字段**：每条有 `claim_id`；`value`/`unit`/`text`/`evidence` 按上；推断/合并的 evidence 以 `[推断]` 开头并写依据。
4. **核对循环**：`check_claims(checklist=[清单项...])` → 有告警则改 → 再 check。
   - **多报/范围外**（含「可能多报」「未匹配任何清单项」类告警）：必须删多余条后再 check；禁止告警后仍带着多报提交。
   - **条数≠N**：不硬卡；并列可多于 N。勿为凑 N 机械删条。其他告警改到能过，或说明对应清单项与处置。
5. **交付**：多轮未解决须说明剩余错误及改不了原因再带错交。原文完全无数字才 `abstained: true` + `claims: []`。有 `<rework>` 时只改所列问题。
