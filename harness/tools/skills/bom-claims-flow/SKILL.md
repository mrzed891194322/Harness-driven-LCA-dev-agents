# BOM 数量抽取 · 02 工作流

按序执行，不扩写。

1. **读技能与题面**：读本技能与题面（plan/query）。
2. **定目标/条数**：**读文前**只依题面定短清单与 N；**读文后严禁反扩清单**。每项「对象×所问指标」；N=len(checklist)。
3. **读原文并抽取**：按清单在 `harness/knowledge/inputs/` 用 `grep` 定位、`read` 确认，写 `workspace/artifacts/bom/claims.json`。薄边界：**原文区间两端可保留**；同一清单项在原文有多个口径或对照值时可并列交；所问项仅给分项时，直接合并值以 `[推断]` 交；**不交**未问分项、同值换单位重复条、定义常数、`value=null`，不换算成题面与原文均未出现的单位。每条有 `claim_id`；`value` 照原文数值与正负号；`unit` 照抄证据完整单位短语；`text` 写口径与文件名+位置；`evidence` 只放含该数与单位的原文逐字引文，推断/合并时以 `[推断]` 开头并写依据。
4. **核对**：调用 `check_claims(checklist=[清单项...])`，同时查数量（条数 vs N）与正确性（value/unit 在 evidence、evidence 在原文）。工具只提醒，不删改、不拦交卷。
5. **交付**：有告警时：逐条写清该 claim 与题面清单哪一项对应，以及改 / 挪笔记 / 保留 / 未解决及理由；**数量告警须单独处理**（不能用 OCR/证据解释一带而过）；**勿为凑 N 机械删条**；改完再核。多轮仍未解决可在 `submit` 说明相关 claim_id、剩余问题及原因后带错提交。原文完全无可答数字才 `abstained: true` + `claims: []`。

有 `<rework>` 时只改所列问题后再交付。
