# 计算基准、比较与解释

- 计算前核对功能单位、定量参考流、参考单位/流属性及实际计算 amount。amount 是目标参考流的数量，不是“一个情景”的倍数，也不因 Product System 写有 targetAmount 就自动采用该值。接口不能显式指定单位时，换算到已核实的默认参考单位；不能核实则停止。
- 比较 calculation-plan、实际调用及 raw 中的设置，确认结果对应报告的分母；报告写明这一对应关系。不以改表头、手动改生成表数值或事后暗乘系数掩盖计算基准错误。
- 计划明确要求的主情景、敏感性分析和指标必须有实际结果；缺少即未完成。未要求的额外分析不一律强制，默认定性讨论关键假设、代理、缺口与不确定性，未分析不得声称稳健。
- 情景比较保持功能等价、功能单位、边界、数据库系统模型、LCIA 方法/版本及计算设置一致，只改变所研究的因素并记录差异。不同情景中的共同缺口不能未经分析就宣称相互抵消。
- 解释重大影响、完整性、敏感性与一致性，回答研究问题并说明局限。运输量大小不直接证明环境影响排序。
- **出处与 fallback**：报告 §6 出处表登记关键解释主张（贡献/热点/改善归因及超出 LCIA 生成表字面值的推断）。`provenance` 仅 `tool_backed`（有正式贡献分解或等价工具 raw）或 `llm_inferred`（无分解工具时，基于 BOM、mapping、类别总量等有依据的叙述）。默认把计划中的贡献/热点类叙述视为可 `llm_inferred`，除非措辞只能理解为需要工具数值分解/贡献百分比且必须来自 openLCA。不得把 `llm_inferred` 写成工具测得结果；不得编造无依据的贡献百分比。不要求用户在 plan 中声明 provenance 或 fallback 许可。
- 核查异常零值、负值和数量级；解释其依据，不能一律删除或截成零。空结果是计算缺失，数值为零不自动代表所有相关流已特征化；工具未提供覆盖证据时不得声称特征化完整。
- 不跨影响类别相加不同单位的数值，不从单一指标推导总体环境优势。结果精度与数据质量相称，结论限定在实际建模范围和可支持的应用；硬计算必做缺失不能用免责声明换取通过。

参数依据：[openLCA CalculationSetup](https://greendelta.github.io/olca-schema/classes/CalculationSetup.html)。
