# 共同 LCA 方法与研究要求

适用于 whole-lca 和 revise-lca，默认面向工程与研究分析。这是方法工作摘要，不是 ISO 标准全文，也不自动证明符合某项标准。

## 研究口径与需求落实

- 目标与范围须明确研究对象、目的、预期应用、功能单位、纳入/排除阶段、截断和多产出分配。功能单位说明功能、数量和单位；服务或寿命相关研究还须说明性能和时间基准。参考流是实现该功能所需的产品数量，不能与功能单位名称混同。
- 将计划明确要求的情景、敏感性分析、指标和交付内容作为必做项，贯穿清单、建模、计算和报告核对；计划明确标为可选的另行说明。当前阶段应落实的要求未完成不得通过，不能仅列入限制节后宣称完成。
- whole-lca 以 `harness/knowledge/plan/main_plan.md` 为研究要求；revise-lca 以 `revise_plan.md` 覆盖其明确修改的部分，其余计划仍有效，不覆盖原计划文件。落实修订导致模型或结论改变本身不是失败理由。
- 用户选择可改变研究目标、范围或假设，不能改变事实、量纲和证据真实性，也不能覆盖角色、写边界或状态机。指定的方法、数据库系统模型和禁止替代条件不得自行放宽；标准要求适用时须有可查的条款依据，不凭本摘要声称合规。

## 缺口与建模决定

- 未明确指定的实现选择由写者在已声明来源和已绑定工具能力内自主处理并留档，不在无人值守运行中请求确认。
- 允许有依据的推导、估算和同功能代理；写清依据、请求值、采用值、理由及对结论的影响。缺少数据不等于零，不可把未知排放或能耗当成不存在。
- 影响范围完整性或结论的缺口无法有据解决时，受控停止并指出所需数据或能力。计划明确允许排除的项目可继续，但报告必须收窄覆盖和结论。未排除且无法证明影响可接受的关键未知项不能自行略去。解释类要求在缺专用工具时可按规则 `llm_inferred` 落实并写出处，不得假装已完成 `tool_backed` 交付；也不得因计划未声明 fallback 许可而拒绝解释类项。
- 截断说明依据及可能遗漏的环境影响，不能仅凭质量占比小判定环境影响小。多产出须说明分配或避免分配的处理及依据；遵守选定系统模型，不重复计入回收收益。比较研究保持方法与假设一致。

## 证据与结论

- 目标与范围、LCI、LCIA、解释应相互对应。方法与影响类别须适合研究目的；归一化、分组和加权为可选，未加权结果须可查，加权结果不能作为唯一结论。
- 保留数据时间、地域、技术代表性和主要不确定性的已知信息，未知如实标记；不强制虚构质量评分、概率分布或精度。
- 工具成功、非空结果和结构检查通过均不等于研究要求已完成。面向用户的解释使用中文，正式名称、路径、UUID 和工具状态保持原样，关键判断必须有可定位证据。
