# 背景适配与前景建模

- 候选先核功能、参考产品、物理量/参考单位、技术路线和系统模型，再比较地域、时间代表性及数据质量。名称相近、UUID 存在或单位相同都不足以证明适配。
- 区分原生/再生、产品/加工服务、货运/基础设施、生产/市场和废物处理。市场可能含生产供应、运输和损耗；显式运输或损耗不得与已有范围重叠。加工数据是否已含原料、聚合数据是否已含某阶段、回收信用是否重复，也须有依据核对。
- 精确地域无候选时，可以选择功能、技术、单位和系统模型适配的区域或其他地域代理，并说明代表性；RoW/GLO 不是强制回退。地域别名不一致本身不构成错配，实际代表性不合适则不能仅靠备注通过。
- 记录请求值、选用值、正式名称/UUID、查询词或证据引用、候选取舍、代表性缺口和限制。无法获得的元数据如实标未知，不从名字推断年份、技术、覆盖范围或数据库版本已获验证。
- 已有背景 Flow、Process/Provider、单位/流属性和方法必须来自正式工具查询；新建前景 Flow、Process、Product System 可生成 UUID，须稳定、一致且不覆盖无关实体，不把自建 UUID 冒充数据库查询结果。导入后核对前景实体和连接。
- 前景聚合允许多条 BOM 行归入同一过程，但要明确每条行的负荷计入何处、是中间连接还是仅作范围记录；排除项不得伪装成已有背景映射。已明确排除的行在说明中留档，不为凑齐字段生成虚假 Provider。
- 用现有工具、资料和数据集文档核查边界；工具未暴露的细节不能当作已检查。若无法排除影响结论的重复计算或功能错配，停止并报告缺口。不能通过更换用户指定方法、系统模型或禁止替代对象来强行完成。

方法参考：[ecoinvent 市场活动](https://support.ecoinvent.org/market-activities)说明市场运输、损耗和直接供应的区别；此链接是规则的方法依据，不额外授权运行任务联网检索。
