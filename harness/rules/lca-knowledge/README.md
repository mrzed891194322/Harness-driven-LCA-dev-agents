# LCA 知识与用户资料规则

本规则适用于开展 Whole-LCA / Revise-LCA 的 Agent。方法条款来自 ISO 14040/14044 系列的工作摘要，不是标准全文。项目事实来自 `harness/knowledge/` 中的用户文件。禁止调用 `query_rag`。

## 用户资料

- 用户参考资料与项目事实只存在 `harness/knowledge/`（扁平目录）。`workspace/inputs/` 仅含 `plan.md` 与 `revise.md`，是工作流结构化输入，不是证据检索域。不要到 `workspace/inputs/references/` 或已删除的 `user_ref` 路径查找副本。
- 需要数值、物料、运输、地域、工艺说明或清单时，直接读取该目录中的文件。按文件名、计划中的路径或简称匹配；匹配到后记录路径和章节/行号。
- 目录为空或找不到引用文件时，记为未解决项或按第 01 阶段规则处理，不得编造数据。
- 证据来源类型：用户文件用 `user-file`；本规则中的方法条款用 `standard`。

## LCA 工作规则（简版）

开展 LCA 时遵守下列要求。与用户计划冲突时，第 01 阶段已确认的用户价值判断优先；本规则用于填补方法空缺和审查口径。

1. **四阶段**：目标与范围定义、清单分析（LCI）、影响评价（LCIA）、解释。不得跳过解释；报告必须覆盖已执行的阶段。
2. **目标与范围**：明确研究对象、研究目的、预期应用和结果解释范围。功能单位须含数值、基准流/功能描述和物理单位。系统边界写明纳入与排除的生命周期阶段。
3. **截断与分配**：给出截断规则或明确不采用截断。多产出时说明是否存在共生产品及分配原则；比较研究中分配方法须一致。
4. **LCI**：前景数据以用户资料为准并回读原文。背景过程、流、Provider 和方法只通过正式 openLCA 工具查询 UUID，禁止臆造。数据缺口、假设和代理选择必须留档。
5. **LCIA**：分类与特征化是强制要素；归一化、分组、加权为可选，选用时须说明方法并不得把加权结果当作唯一结论。
6. **解释**：对照目标与范围识别重大问题、完整性/敏感性/一致性，给出结论、局限和建议。不得用工具成功调用替代阶段通过。
7. **报告**：面向用户的说明使用中文；路径、UUID、工具原始状态保持原样。关键事实必须可追溯到用户文件位置或 openLCA 实体 UUID。

openLCA 软件操作、导入范围和匹配决定遵守 `harness/rules/openlca-operation/README.md`，不依赖已移除的手册原文。
