# 清单完整性与数量基准

适用于 02 提取和 03 建模。JSON 字段由阶段契约规定，推导和覆盖说明写入既有 Markdown 产物。

- 按系统边界核对物料、能源、水、运输、直接排放、废物及共同产品；说明各生命周期环节如何覆盖。不能将物料 BOM 等同于完整 LCI，也不能因为资料没有某项就认定它不适用。
- 每个数量明确对应单件、批次、时间段或功能单位；保持情景和基准可辨认。记录源数值、单位、缩放系数与公式，区分采购量、投入量、净产品量、收率和损耗，不重复展开上下层 BOM。
- 换算检查量纲：质量与体积换算需要密度及条件；能源换算区分物理单位与热值口径；运输量是承运质量乘距离，核对湿/干质量、空瓶/满载产品、运输区段和已有数量是否已乘距离。`kg·km` 换为 `t·km` 除以 1,000，不再重复乘重量或距离。
- 将源数据 → BOM 数量 → exchange 数量 → 定量参考 → 所需计算 amount → 报告功能单位连成可复算链条。02 给出源数据到 BOM 的推导；03 完成模型和计算基准。不能同时按功能单位写入输入又再次按批量缩放。
- 区分已知零、未知、计划允许排除和不适用。未知 quantity 用 null 并保持 partial/unreadable 等既有状态及缺口说明，不用 0 占位；这些说明不增加 extraction_status 枚举。
- 在资料足以核对的过程或环节做适度质量/能量平衡与数量级检查，记录差额、原因和限制；不对不适用的聚合边界强造平衡，不为配平虚构流量。
- 工序列名或映射到聚合过程不证明其负荷已建模。须能指出实际计入的输入/输出；缺失能耗、损耗和排放按共同缺口规则处理。
